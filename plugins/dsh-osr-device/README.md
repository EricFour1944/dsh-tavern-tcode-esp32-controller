# dsh-osr-device

让 **dsh-tavern** 的正文驱动本地 **OSR2 / SR6 中文控制器**（`http://127.0.0.1:8899`）。
全局插件：装上后每一局都生效；不想用可在「设置 → 酒馆插件」里停用，或在某局的本局设置里关掉。

## 安装

1. 启动控制器（桌面 `启动控制器.bat`）；
2. 把本文件夹复制到 Tavern 插件目录：

```text
~/.dsh/profile-data/tavern/data/plugins/dsh-osr-device/
├─ package.json
├─ index.mjs
└─ README.md
```

3. **重启 DSH**（宿主侧 `index.mjs` 的首次加载与任何修改都需要重启）；
4. 打开 Tavern → 设置 → DSH Tavern → 插件，确认状态是「已加载」。

## 两种触发方式

### 1. 代码块指令（推荐，确定性最高）

插件通过 `promptSection` 告诉模型这样写：

````text
```osr
{"group":"前戏·慢"}
```
````

- 组名必须来自控制器「🔌 联动」里已有的动作组；
- 支持 `{"group":"…","gain":0.9,"bpm":80}`（幅度 0.2–1.6，速度 10–240）；
- 支持停止：```` ```osr {"stop":true} ``` ````；
- Tavern 会把程序块从正文里去掉，玩家看不到这段指令（`rawText` 里保留，插件从这里解析）。

**默认只有玩家明确要求时才执行**：本局设置里的「允许模型自主决定动作」默认关闭，
模型自己写的 `group` 会被忽略，避免剧情跑偏时突然换动作。

### 2. 关键词兜底

本局设置里「无指令时用关键词匹配」默认开启：没有 `osr` 指令时，插件把正文交给
控制器，由「联动」里配置的关键词表决定播什么（例如 `亲热 → 前戏·慢`）。

### 3. AI 编排（L1：自己组合一段，只播一次）

模型可以用**单独的标记块**自己拼一段动作组合，插件校验后调
`POST /api/ai/strokes` 播放——**不写进动作库**，播完就结束：

````text
```osr-compose
{"compose":[{"stroke":"down-forward","bpm":40,"secs":20},
            {"stroke":"back-thrust-down","bpm":65,"secs":15}],
 "gain":0.7,"label":"慢起快收"}
```
````

- **标记、开关、上限都在控制器里改**（联动页 →「AI 编排（L1）：标记与上限」）：
  `tag`（默认 `osr-compose`）、是否启用、最多段数、单段最长秒数、BPM 上限；
- 插件**每轮读一次**控制器配置（3 秒缓存），所以改完标记**立刻生效，不用重启酒馆**；
- 编排协议会通过 `turnSection` 自动写进提示词，连同**动作库现有英文名清单**，模型不用猜；
- 名字不在动作库里的段会被丢弃；`bpm/secs/gain` 由插件夹一次、控制器再夹一次；
- 播放走「临时组」，占用的是同一套安全限幅（行程窗口、速度上限、急停）。

## 本局设置项

| 项 | 默认 | 说明 |
|---|---|---|
| 启用设备联动 | 开 | 关掉后本局不再发任何指令 |
| 允许模型自主决定动作 | 关 | 打开后模型自己写的 `group` 也会执行 |
| 无指令时用关键词匹配 | 开 | 走控制器的关键词表 |
| 最短间隔（秒） | 20 | 冷却，避免每轮重播 |
| 幅度（%） | 60 | 换算成控制器 `gain`，60% = 原始幅度 |

## 给界面用的入口

浏览器侧插件可以用 `tavernUi.callHost` 调用：

| 入口 | 作用 |
|---|---|
| `dsh-osr-device/play` `{group}` | 手动播一个动作组 |
| `dsh-osr-device/stop` | 停止（软停止，不锁存急停） |
| `dsh-osr-device/state` | 读控制器 `connected / mode / estop / position` |
| `dsh-osr-device/groups` | 读动作组列表与关键词绑定 |

## 安全

- 控制器页面上的「急停 / 全部停止」优先级最高，插件无法绕过；
- 行程安全窗口（默认 25%–75%）与速度上限由控制器强制，插件改不了；
- 控制器没启动时插件静默跳过（只记一条日志），不影响正文与游戏流程；
- 只访问 `127.0.0.1`，不发任何外部请求。

## 排错

| 现象 | 处理 |
|---|---|
| 设置里显示「启动失败」 | 看插件目录下的 `.tavern-status.json` 的 `message`，改完 `index.mjs` 需重启 DSH |
| 日志出现 `未触发：not_connected` | 控制器没连上设备，先在控制器页面点「连接」 |
| 有 `触发动作组 xxx` 但设备不动 | 检查控制器 `mode`、急停、行程窗口 |
| 完全没反应 | 确认本局设置里「启用设备联动」是开的，控制器端口是否为 8899 |

## 三层判定链（0.2.0 起）

每一轮在「本轮结算完」之后，按下面的顺序决定要不要动、动哪一组。**命中即返回**，三层绝不叠加下发：

| 层 | 依据 | 成本 | 说明 |
|---|---|---|---|
| ① 显式指令 | 正文里的 `osr` / `osr-compose` 代码块 | 0（提示词已含） | 最高优先级，模型/玩家明确指定的组 |
| ② 关键词 / 组名 | 控制器里绑定的关键词，或组名直接出现在正文里 | 0 | 规则匹配，毫秒级 |
| ③ 后台判断 | 预留位（导演成员），默认关闭 | 每轮一次小调用 | 前两层都没命中时才用 |

## 两个开关（控制器 → 联动 → AI 编排 下方）

| 开关 | 默认 | 作用 |
|---|---|---|
| 教模型写指令块 | 开 | 关掉后前台提示词不再教模型写 `osr` 块，正文更干净；**老卡自己写的块仍能被识别**（解析与注入是两件事） |
| 回退时停设备 | 开 | 玩家回退 / 重新生成 / 编辑正文时，设备立刻停下，不继续演旧剧情 |

## 后台任务

插件用 `tavern.job({ name: 'drive', on: 'turn-settled' })` 注册，所以会出现在 Tavern 的
「后台任务」页（名字前带 `插件「dsh-osr-device」`），失败也记在这里，不用翻控制器日志。
旧版 Tavern 没有 `job()` 时自动退化为 `onTurnSettled`，行为不变。
